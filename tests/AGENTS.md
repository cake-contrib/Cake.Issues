# Integration tests and report demos

Follow [the shared instructions](../AGENTS.md).

## Running integration tests

Each addin has a directory here, with `script-runner/<TFM>` tests and, where
applicable, `frosting/<TFM>` tests. Select an existing framework directory
(`net10.0` or `net11.0`) for the affected addin.

Create local NuGet packages from the repository root **before** running any
integration test:

- Bash: `./build.sh --target=Create-NuGet-Packages`.
- PowerShell: `.\build.ps1 --target=Create-NuGet-Packages`.

Then run the selected test (typically about 15 seconds):

```bash
cd tests/Cake.Issues.MsBuild/script-runner/net11.0
./build.sh --verbosity=diagnostic
```

```powershell
Push-Location tests\Cake.Issues.MsBuild\script-runner\net11.0
.\build.ps1 --verbosity=diagnostic
Pop-Location
```

Validate both runner styles when applicable.

## Report generation

- Keep Console report-generation tasks and sample data under
  `Cake.Issues.Reporting.Console/script-runner/net10.0/build/create-reports`,
  following the Generic report-format demo tests.
- Follow [docs/AGENTS.md](../docs/AGENTS.md) for Console screenshot regeneration.
- Generic report demos are generated by integration-test tasks. Use the
  `update-dxdatagrid-theme-docs` skill and keep demo tasks aligned across the
  Cake Scripting and Cake Frosting runner variants.

## Troubleshooting

- Missing packages: build local packages first.
- Package version mismatch: inspect the specific affected `cake.issues*` cache
  entries in `~/.nuget/packages` (Bash) or
  `$env:USERPROFILE\.nuget\packages` (PowerShell). Remove only confirmed stale
  package directories, then rebuild packages.
- Test failures: check that the selected framework directory exists and that
  its SDK is installed.
- Permission denied in Bash: the selected test's `build.sh` may need
  `chmod +x build.sh`.
